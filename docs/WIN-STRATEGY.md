# 开源增长与传播设计（合规）

> 本大赛排名**完全依据 GitHub 公开 Star 数**（Star>0 进榜，前 100 名获奖，定榜取 2026-10-26 00:00 数据）。
> 官方规则**明令禁止机器人、群控、批量注册账号、互刷等任何形式的刷榜**，违者取消资格。因此本文只讨论**如何把项目做得真正值得 Star、并合规地让更多开发者看到**——靠产品力与正当传播，而不是数据造假。

## 1. 为什么这样设计：把"投票理由"做进产品里

开发者愿意为一个项目点 Star，通常因为它**有用、有趣、能玩、值得学、值得晒**。mcctl 同时占住这五点：

| 投票理由 | 对应设计 |
|---|---|
| 有趣 / 想晒 | `mcctl whoami` 麦麦人格测试 + 8 型人格 + 可下载 / 分享的像素风"麦籍卡" |
| 零门槛能玩 | 纯静态网页 Playground（不装环境就能测）；CLI 无 Token 也能离线 Mock 全流程 |
| 真有用 | `save` 一键领券 + 凑单 + 真实到手价；`diet` 控卡高蛋白；`order` 安全下单闭环 |
| 接得全 / 值得学 | 官方 35 个 MCP 工具全量接入；真实 / Mock 双客户端、组合搜索引擎、完整测试与架构文档 |
| 有记忆点 | 名字 `mcctl`（对标 kubectl）、程序员节梗、麦当劳配色、终端 demo、幸运命令 |

## 2. 差异化（相对同赛道常见作品）

- 同赛道多为"单点查热量 / 算卡路里 / 省钱"脚本；mcctl 是**覆盖全 35 工具的完整控制面**，且有 CLI + Skill + 网页三位一体形态。
- 别人只有功能，mcctl 有**社交裂变入口**（人格测试 / 麦籍卡），把每个体验者变成传播节点。
- 别人多需 Token / 配置才能跑；mcctl **clone 即用、一条 `mcctl demo` 出片**，降低 Star 与二创门槛。
- 强调**工程质量与安全**：41 个测试、CI、交易护栏、字段容错、真实 / 离线一致，便于技术读者认可。

## 3. 合规传播清单（可以做）

1. **把网页 Playground 部署到 GitHub Pages**，README 顶部放"🃏 立即测麦麦人格"直达链接——让不点命令行的人也能 8 题玩到并回流 Star。
2. **准备一条高质量演示视频 / GIF**：按 [`docs/DEMO.md`](DEMO.md) 的脚本，突出人格测试 → 命定套餐 → 46 元省到 36 → 安全下单。
3. 在**开发者社区正当分享**：V2EX、掘金、少数派、即刻、小红书、B 站、知乎、X、Reddit（r/SideProject 等，遵守各版规，标注原创与非官方）。
4. 写清楚**技术亮点**：MCP 双客户端与自动降级、组合搜索配餐、券门槛 / 单品 / 组合校验、安全护栏——吸引工程师 Star 与 Fork 二创。
5. **及时回应 Issue / PR**，鼓励别人加新人格、新餐品、新语言，把 Star 沉淀成社区。
6. 在麦当劳官方活动仓库**按要求发报名 Issue**（标题自定义、正文≤1000 字、不带图），确保进入榜单采集。
7. 提交 `workbuddy.md` 获取 WorkBuddy 联动积分，并可在 WorkBuddy 社区展示。

## 4. 红线（绝不做）

- ❌ 机器人 / 脚本批量点 Star、群控、购买 Star、批量注册账号、互赞互刷群；
- ❌ 冒充麦当劳官方、使用官方商标 / Logo 做误导性陈述、把演示数据伪装成官方实时数据；
- ❌ 在仓库或材料中放真实 Token、密钥、他人个人信息；
- ❄️ 项目中已包含官方要求、**一字未改**的 `CONTEST_DECLARATION.md`，并在显著位置标注"非官方创意作品"。
